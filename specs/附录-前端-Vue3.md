# 附录：前端 Vue 3

> 只写**换项目仍成立**的前端约束。标「示例」的条目来自具体项目，进入新仓库前先确认，**不要默认套用**。

## 1. 组件与目录约定

- 先确认目标仓的目录职责划分（页面 / 组件 / 路由 / 公共样式 / 工具 / 接口封装）与入口文件，再决定改哪里。
- 新文件优先使用 **Vue 3 组合式 API**；已有文件保持当前语法风格即可，不强制重写（重写会制造巨大 diff，收益低风险高）。
- 复用现有组件与工具方法，只有现有模式无法表达新需求时才新增抽象。

## 2. 新增展示内容的硬前提

- 任何**新增展示字段、筛选条件、统计值、状态标签**，都必须先确认：来源字段、接口路径、后端映射或算法输出。
- 无法确认来源时**不得实现为空占位逻辑**；前端不得自行发明字段。
- **界面上不展示 ID 字段和值**（示例：ID 仅供业务与开发使用，不是用户可读信息）。

## 3. 不兜底

- **未经明确要求不做业务兜底逻辑**；兜底不能掩盖错误的验证结果。
- 后端数据质量、接口契约、依赖服务与持久化异常，应由后端明确抛出并返回可定位信息，**前端不负责替后端兜底**。
- 前端只处理：前端输入校验、交互状态、页面渲染、客户端可判定的错误。

## 4. 状态与边界（逐项检查）

新增或修改功能时，必须检查：

- 初始态、加载态、成功态、**空态**、失败态；
- **重复触发**（连点、重复请求）、取消 / 关闭 / 切换后的状态清理；
- 长文本、空字段、异常字段的渲染；
- **异步请求返回顺序**对 UI 的影响（后发先至、竞态）；
- 弹窗 / 抽屉关闭后的状态残留。

涉及布局、弹窗、表格、看板或复杂交互时，至少**静态检查**：响应式、空态、加载态、错误态、长文本溢出。

## 5. 异步与接口调用

- 接口调用集中在项目既有的接口封装目录，不在组件里散写请求。
- 请求失败要有明确口径：提示什么、状态怎么回退、是否可重试；不同时用两套提示机制。
- 懒加载的候选数据要挂对时机（示例：某组件库的 popover 只有 `before-enter`，没有 `show` 事件）——**挂错时机的表现是"历史已选数据从不触发加载、下拉全空"**，排查时优先看触发时机而不是接口。
- 已选值的"兜底回显项"不能被当成"候选已加载"的证据。

## 6. 样式

- 保持现有 UI 风格一致；新界面简约、整齐、符合使用习惯。
- 具体语法禁忌按目标仓约定（示例：某仓禁止使用 CSS `gap`）。**进入新仓先看该仓是否有此类禁令**，不要跨仓套用。

## 7. 路径假设

- 现有接口路径、工具路径、组件路径**默认是正确的**，除非有明确证据证明有问题；实现功能和排查时不要在无关场景反复怀疑这些路径（会浪费大量轮次）。

## 8. 测试与验证

- **未经明确要求不生成测试代码。**
- 默认不主动做浏览器验收；用户明确要求页面验收 / 截图 / 联调时才操作浏览器，失败时只说明实际现象。
- 即使不跑构建，也要做最小静态复核：import、类型、字段名、契约、空占位、死代码、未使用变量。

## 9. 交付要求

- 说明**方法流转**（数据从哪来、经过哪些方法、最后怎么渲染）、实现方式，以及每个改动方法的作用。
- 未做真实接口联调时必须明说未联调，并列出未验证边界。
