# 附录：后端 Java / Spring Boot

> 只写**换项目仍成立**的后端约束。标「示例」的条目来自具体项目，进入新仓库前先确认该仓是否同样要求，**不要默认套用**。

## 1. 分层与入口

- 典型分层：Controller（接口）→ Service / ServiceImpl（编排与业务）→ Mapper（数据访问）；新增功能按数据层、服务层、控制层形成闭环，不要跨层直连。
- 先确认本仓的聚合模块与启动入口，再决定改哪个模块；多模块仓库要注意各模块的**编译级别可能不同**（示例：一个模块按 Java 11 写，另一个模块须保持 Java 8 兼容），语法特性按目标模块的编译级别选。
- 文件路径处理优先使用 `java.nio.file.Paths.get(...)`，避免直接使用较新的 `Path.of(...)`，除非已确认编译级别与运行环境都支持。

## 2. 接口契约

- 返回结构与字段清单一旦变化，**必须同步修改调用方，并同步更新接口注释**；接口注释要写明使用方式，并在 `@return` 中列出 JSON 结构。
- 契约变更顺序：先确认提供方返回结构 → 再改调用方类型与解析 → 最后调展示层。
- 不得为了页面临时展示返回**无来源字段**或空占位字段。
- 类级路由注解、返回类型包装等写法**按目标仓既有约定**（示例：统一 `ResponseEntity<Map<String, Object>>`；新建 Controller 不加类级 `@RequestMapping`）。进入新仓先看现有 Controller 怎么写。

## 3. 依赖注入

- 优先构造器注入，字段用 `private final`；配合 `@RequiredArgsConstructor` 减少样板代码。
- 不新增字段注入（`@Autowired` 打在字段上）。

## 4. 注释要求（后端强制项）

- **新增方法**，以及本次修改过且**职责、入参、返回或异常语义发生变化**的方法，必须提供方法级 JavaDoc：方法职责、关键参数含义、返回含义、可能抛出的业务异常。
- Controller、Service、ServiceImpl、Mapper、DTO 辅助方法、私有业务方法都不能漏。
- **未触碰的历史方法不要求为满足规则而批量补注释**（避免制造巨大噪音 diff）。
- 关键实现处补内部注释：数据来源、业务规则、异常触发条件、分支意图、非显而易见的转换、以及不做兜底的原因。

## 5. 异常归属（最容易出错的一条）

- **属于本服务的错误必须由本服务明确抛出或返回可定位的错误**：数据库/依赖服务/文件/消息返回缺失、业务数据不一致、必需字段缺失、计算无法完成、持久化失败等，都属于后端职责。
- **不得把后端数据异常静默返回给前端**，让前端用空值、默认值或页面提示代替后端错误处理。
- 前端只负责前端输入、交互状态、页面渲染和客户端校验类异常；后端不能要求前端识别或兜底后端的数据质量、接口契约、依赖服务和持久化异常。
- 修复问题前先判断归属：数据源、接口契约、状态同步、时序、缓存、展示、异常处理、配置还是运行环境；**修复点放在归属层**。
- 只能做临时兼容时，必须写明触发条件、兼容边界、不会掩盖哪些数据问题、以及后续应收口的位置。

## 6. 持久层

- 单表操作优先使用 ORM/框架提供的 wrapper 方法；多表操作放在 mapper XML 中实现并在 mapper 接口声明。
- 建表 / 新增字段脚本必须补齐**表注释和字段注释**，不能只写 `CREATE TABLE`。
- 涉及库表结构、SQL、Mapper 或持久化字段时，先确认是否已有 migration、初始化 SQL 或表结构文档，并确认 DTO、Entity、Mapper/XML、调用方字段与**真实字段一致**；无法确认字段真实存在时，不得只改查询或使用侧而继续实现。
- 写操作（DDL/DML）默认不执行，详见《附录-数据-SQL与数据库.md》。

## 7. 安全与改动纪律

- 不随意修改配置文件（YAML/Properties）；确有必要时先说明原因并取得确认。
- 未经确认不删除文件。
- **不增加无意义的日志**；敏感信息不得进日志。
- 改现有方法时优先改原方法，**不要平行新增一个新方法来替代它**（见正文 5.3）。
- 与本任务无关的模块、配置文件、依赖版本不要顺手改。

## 8. 验证

- 按改动风险执行必要测试、编译或构建验证，交付时说明**验证命令与结果**；未执行就说明原因。
- 不为"凑测试"生成无意义测试代码；新增测试必须服务于真实风险。
- 无法做真实依赖验证（数据库、缓存、消息队列、配置中心）时，不得把"本地编译通过"表述成"联调通过"。

## 9. 排查入口

- 接口问题先看 Controller → Service → Mapper 链路，确认字段从哪来、在哪转换。
- 数据问题先确认表与字段真实存在（见正文第 4.1 节的数据来源三分类），再往下追。
