# 附录：数据、SQL 与数据库

> 只写**换项目仍成立**的数据侧约束。标「示例」的条目来自具体项目，进入新仓库前先确认，**不要默认套用**。

## 1. 只读优先，写操作落盘待人工执行（铁律级）

- 通过工具/插件访问数据库时，**默认只允许查询**：
  - 关系型数据库：仅 `SELECT`。
  - 图数据库：仅只读查询（`MATCH` / `RETURN` 等），不得包含写子句。
- **禁止执行任何写操作**：`INSERT` / `UPDATE` / `DELETE` / DDL（`CREATE` / `ALTER` / `DROP`）/ `TRUNCATE` / `GRANT`，图数据库的 `CREATE` / `MERGE` / `SET` / `DELETE` / `DETACH DELETE`。**即使工具暴露了写能力，也不得调用。**
- 确有写操作需求时：把**完整 SQL 记录成 `.sql` 文件**，保存到目标项目文档目录（示例：项目 `docs/` 下的 SQL 记录目录；无该目录时按项目约定创建），命名建议 `<日期>-<用途描述>.sql`。
- 生成 SQL 文件后**停止**，等待人工执行；用户反馈执行结果后再继续。
- 不通过 shell、脚本或其他绕过方式直连数据库执行语句。
- **禁止为了把界面填满而编造数据、伪造查询结果或使用空占位字段**——数据来源不明就先停下来问（正文第 4.1 节）。

## 2. 字段真实存在性

- 讨论任何字段前，先确认它真实存在：以表结构文档、DDL、实体类、Mapper/XML、接口返回证据为准。
- DTO、Entity、Mapper/XML、调用方、展示层字段必须一致；不一致时先定位以谁为准，不要用"相似字段"顶上。
- 无法确认字段存在时，**说明缺失证据、停止实现**，不得只改一侧查询或使用侧继续往下做。

## 3. 建表与变更脚本

- 建表脚本必须同时补齐**表注释与字段注释**：不能只写 `CREATE TABLE`，还要有表注释和每个字段的注释。
- 涉及结构变更前，确认是否已有 migration、初始化 SQL 或表结构文档，按项目既有方式变更，不另起一套。
- 结构变更是 L 级任务：先出方案（影响范围、回滚方式、是否影响存量数据）再执行。

## 4. 查询写法

- 单表操作优先使用框架提供的 wrapper/查询构造方法；多表关联放在 mapper XML 或项目指定的位置实现并声明。
- 避免不必要的查询：循环里查库（N+1）、重复查询同一份数据、无分页的全表扫描。
- 数据量扩大 100 倍时最先崩的位置通常是：无索引过滤、无分页查询、循环内查询、大结果集全量加载到内存——写查询时主动检查这四点。

## 5. 安全

- 参数化查询/预编译，禁止字符串拼接 SQL。
- 结果集中敏感字段（身份信息、联系方式、凭据）按需脱敏；**不把连接串、账号、口令写进代码、日志或文档**。
- 只读账号与写账号分离，按最小权限使用。

## 6. 排查与验证

- 数据问题先确认三件事：**表与字段真实存在**、**数据来源可证明**、**当前值属于"实际值"还是"兜底值"**。
- 无法连库或没有真实数据时，明确写"未做数据验证"，不得用推测值替代结论。
- 查询结果、核对报告、导出文件属于任务产物，放项目文档目录，不写入系统临时目录或其他项目目录。
