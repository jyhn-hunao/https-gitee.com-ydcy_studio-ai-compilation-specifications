# 附录：用户画像

> 这份文件回答「跟我协作的人是谁、他怎么工作」，让 AI 在方案粒度、确认节奏、交付形态上少猜。
> ⚠ 含姓名、部门、邮箱等个人信息；若本仓要公开分发，先把第 1 节脱敏，或改成只留指针。

## 0. 边界

- **是**：身份、工作背景、协作习惯的事实记录；与用户当轮指令冲突时以当轮为准。
- **不是**：铁律或偏好的替代。写代码铁律在主规范 §2/§3/§5/§6/§7；可执行偏好条目在 `个人偏好.md`（U6–U8）。
- **不复制**：第 3 节只给章节指针，不复述条文（复述一次就多一份会漂移的副本）。
- **与 mnemon 的关系**：原文 `~/.mnemon/runtime/USER.md` 只读留档，不再作为事实源；本文件更新后以本文件为准。

## 2. 协作习惯

| 场景 | 做法 |
| --- | --- |
| 工作区外改动 | 涉及 `~/.dsh` 配置、系统配置或安装第三方插件时，先给推荐方案 + 配置片段，等确认再执行 |
| 设计粒度 | 默认按**最终形态**设计（如一开始就做多实例并发保护），不做「先简单、后返工」的过渡实现；明确要求分阶段时例外 |
| 澄清节奏 | 需求细节**逐个提问、逐个确认**，不要一次抛出全部待确认项；当轮明确要求「一次问清」时按当轮 |
| 语言 | 中文交流、中文回复；代码里的编号注释也用中文 |
| 交付 | 结论先行、证据表随后；不复述已经说过的内容 |

## 4. 维护

- 只在本人明确表达后新增或修改；一次一条，写清日期与来源。
- 身份信息变化（部门、提交身份）在同一轮更新本文件；不要在项目规则里再抄一份。
